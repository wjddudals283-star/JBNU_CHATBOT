# 구글폼 응답 제출 도구 (gform-submit)

CSV 한 줄을 구글폼 응답 하나로 제출한다. 종이 설문을 옮길 때, 다른 곳에 모인 답을
폼 집계로 합칠 때, 만든 폼을 여러 답으로 시험할 때 쓴다.

> **이 도구는 응답을 지어내지 않는다.** 답은 사람이 만든 CSV 에서만 온다.
> 무작위 응답 생성 기능은 의도적으로 없다. 본인이 만들었거나 제출 권한이 있는 폼에만 쓴다.

---

## 설치

```bash
cd gform-submit
pip install -r requirements.txt
```

Python 3.11 이상. 구글 계정·API 키가 필요 없다 — 브라우저가 하는 것과 같은 요청을 보낸다.

---

## 쓰는 순서

### 1. 문항 구조 확인

```bash
python -m gform inspect "https://docs.google.com/forms/d/e/<ID>/viewform"
```

```
폼: 행사 참가 신청   (id 1FAIpQLSe…, 2페이지)
  entry.1001       단답    필수  이름
  entry.1002       객관식   필수  소속
      선택지: 공과대학 / 인문대학  (+기타 입력 가능)
  entry.1003       체크박스  선택  관심 세션
      선택지: 세미나 / 워크숍 / 네트워킹
  entry.1007       날짜    선택  참여일
      형식: YYYY-MM-DD
  ✗ 건너뜀(파일 업로드는 지원 안 함): 증빙
```

`forms.gle/…` 단축 주소도 된다.

### 2. CSV 템플릿 만들기

```bash
python -m gform template "<폼주소>" -o answers.csv
```

헤더만 있는 CSV 가 생긴다. 칸 이름은 문항 제목이다. 그리드는 `문항 » 행`.
제목이 겹치면 `제목 [entry.N]` 으로 갈라 준다. 헤더를 `entry.N` 으로 직접 써도 된다.

### 3. 답 채우기

| 유형 | 쓰는 법 |
|---|---|
| 단답·장문 | 그대로 |
| 객관식·드롭다운·배율 | 선택지 글자 **그대로** |
| 체크박스 | `세미나\|네트워킹` (`--sep` 로 구분자 변경) |
| 객관식 "기타" | 선택지에 없는 값을 쓰면 기타로 들어간다. 기타가 없는 문항이면 오류 |
| 날짜 | `2026-09-10`, 시각 포함 문항은 `2026-09-10 14:30` |
| 시각 | `09:30`, 기간 문항은 `01:30:00` |
| 이메일 수집 폼 | `emailAddress` 칸 |

첫 칸이 `#` 으로 시작하는 줄은 메모로 보고 건너뛴다. 빈 칸은 "답 안 함".

### 4. 검증만 먼저

```bash
python -m gform submit "<폼주소>" answers.csv --dry-run
```

모든 줄을 검증하고 실제로 보낼 필드를 출력한다. **한 줄이라도 틀리면 한 건도 보내지 않는다.**

```
CSV 검증 실패 — 한 건도 보내지 않았습니다
  3행: [소속] 필수 문항이 비어 있습니다
  7행: [학년] 선택지에 없는 값입니다: '3'. 가능한 값: ['1', '2']
```

### 5. 제출

```bash
python -m gform submit "<폼주소>" answers.csv --report result.csv
```

건수를 한 번 묻고 보낸다. 기본 간격 2초 (`--interval`). 결과는 줄마다 `result.csv` 에 남는다.

| 옵션 | 뜻 |
|---|---|
| `--yes` | 확인 질문 생략 |
| `--limit N` | 앞에서 N줄만 (한 건 먼저 보내보고 폼 응답에서 확인할 때) |
| `--interval 초` | 제출 간 최소 간격. 기본 2 |
| `--stop-on-fail` | 첫 실패에서 중단 |
| `--sep` | 체크박스 구분자. 기본 `\|` |

## 되는 것 · 안 되는 것

| 되는 것 | 안 되는 것 |
|---|---|
| 단답·장문·객관식·드롭다운·체크박스·배율·그리드·날짜·시각 | **파일 업로드** (로그인 필수라 구조적으로 불가) |
| 여러 페이지 폼 | **로그인 필요 폼** ("응답자 제한", "응답 1회로 제한") |
| "기타" 입력 | 응답 수정 링크·부분 저장 |
| 이메일 수집(응답자 입력 방식) | 이메일 수집(인증 방식, 로그인 필요) |
| `forms.gle` 단축 주소 | 구글이 봇으로 판단해 CAPTCHA 를 띄우는 경우 |

## 실패가 조용한 이유와 대처

구글은 검증에 걸린 제출도 **HTTP 200 으로 폼을 다시 그려서** 돌려준다. 상태코드로는
성공과 실패를 못 가른다. 그래서

1. 보내기 전에 우리가 필수·선택지·형식을 먼저 검사하고
2. 응답 본문에 폼 데이터(`FB_PUBLIC_LOAD_DATA_`)가 다시 들어 있으면 거절로 본다.

`--limit 1` 로 한 건 보내고 폼의 "응답" 탭에서 실제로 들어갔는지 확인한 뒤 나머지를 보내는 것을 권한다.

## 구조

```
gform/schema.py    viewform HTML → Form/Question   (FB_PUBLIC_LOAD_DATA_ 해석)
gform/payload.py   답안 → (name, value) 목록 + 검증
gform/client.py    가져오기 · 제출 · 성공 판정
gform/cli.py       inspect / template / submit
tests/             픽스처 HTML + MockTransport. 실제 구글에 붙지 않는다
```

폼 페이지의 데이터 구조는 공식 스키마가 아니라 **관측**이다. 구글이 바꾸면 `schema.py` 가
먼저 깨진다. 그래서 인덱스 접근은 전부 `_at()` 으로 감싸 예외 대신 None 으로 떨어지게 했고,
`inspect` 결과가 폼 화면과 다르면 그 지점이 바뀐 것이다.

```bash
python -m pytest -q      # 51개
```
