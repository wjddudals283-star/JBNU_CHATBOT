# 학식 자동 수집 — 대표 PC 설정 (화면 순서대로)

한 번만 설정하면 됩니다. **그 뒤로는 컴퓨터를 켜기만 하면 됩니다.**

---

## 왜 이 PC 에서 도나요

생협 식단 API 가 **해외 IP 를 막습니다.** 우리 서버는 싱가포르에 있어서 못 가져옵니다.
오늘 서버에서 직접 확인한 결과입니다.

```
curl 그대로              403 · 318바이트
브라우저인 척 (UA)        403 · 318바이트
브라우저인 척 + Referer   403 · 318바이트
```

**요청을 어떻게 꾸며도 응답이 한 바이트도 안 바뀝니다.** 헤더가 원인이 아닙니다.
그리고 이게 '한국 밖이라 막는 것' 인지 '데이터센터라 막는 것' 인지 **구별이 안 됩니다.**
후자라면 클라우드 서버를 한국에 새로 만들어도 똑같이 막힙니다 —
그래서 검증 안 된 가정 위에 계정·카드·서버를 쌓지 않기로 했습니다.

대표님 PC 는 **가정용 한국 IP** 라 그 위험이 없습니다. 실제로 여기서는 `200` 이 나옵니다.

---

# 1단계 — 파이썬이 있는지 확인

`시작` → `powershell` 입력 → 열린 창에 아래를 붙여넣고 Enter.

```powershell
py --version
```

`Python 3.x.x` 가 나오면 됩니다.
`인식할 수 없는` 이라고 나오면 https://www.python.org/downloads/ 에서 설치하고,
설치 화면 **맨 아래 `Add python.exe to PATH` 를 반드시 체크**해 주세요.

---

# 2단계 — 토큰을 시스템 환경 변수에 넣기

## 토큰 값 가져오기

1. https://dashboard.render.com 로그인
2. `jbnu-chatbot` 서비스 클릭
3. 왼쪽 `Environment` 클릭
4. `SKILL_TOKEN` 줄의 눈 아이콘(👁) 을 눌러 값을 보이게 하고 **복사**

## 윈도우에 넣기

★ **반드시 `시스템 변수`** 에 넣어야 합니다. `사용자 변수` 에 넣으면
  작업 스케줄러가 다른 계정으로 돌 때 못 봅니다.

1. `시작` → `환경 변수` 라고 입력 → **`시스템 환경 변수 편집`** 클릭
2. 창 아래쪽 `환경 변수(N)...` 버튼 클릭
3. **아래쪽** `시스템 변수(S)` 칸에서 `새로 만들기(W)...` 클릭
4. 이렇게 입력

```
변수 이름 :  SKILL_TOKEN
변수 값   :  (복사한 값 붙여넣기)
```

5. `확인` → `확인` → `확인` (세 번 다 눌러야 저장됩니다)
6. **열려 있던 PowerShell 창을 모두 닫습니다.** 새로 열어야 값이 보입니다.

## 잘 들어갔는지 확인

새 PowerShell 창을 열고:

```powershell
if ($env:SKILL_TOKEN) { "토큰 있음" } else { "토큰 없음" }
```

★ 토큰 값 자체를 화면에 띄우지 마세요. 있는지만 확인하면 됩니다.

# 3단계 — 손으로 한 번 돌려 보기

자동으로 걸기 전에 **먼저 손으로 성공시켜야 합니다.**
안 되는 걸 자동으로 걸면 조용히 안 되는 상태가 됩니다.

`jbnu-chatbot\scripts` 폴더에서

```
학식_지금_보내기.bat   ← 두 번 클릭
```

성공하면 이렇게 나옵니다.

```
2026-08-14 19:12:45  시작
    서버: https://jbnu-chatbot.onrender.com
      [coop_week_menu] fetch 200  16,515B
    → 서버 success  식단 95건 / 격리 0  OK
2026-08-14 19:12:48  성공  1/1 성공
```

★ `fetch 200` 이 이 PC 에서 생협 자료를 받았다는 뜻입니다.
★ `서버 success` 가 우리 서버에 들어갔다는 뜻입니다.

**여기서 실패하면 4단계로 가지 마세요.** 바탕화면에 생긴
`★학식_수집_실패.txt` 를 열면 원인이 적혀 있습니다.

---

# 4단계 — 작업 스케줄러에 걸기

1. `시작` → `작업 스케줄러` 입력 → 실행
2. 오른쪽 `작업 만들기...` 클릭 (★ `기본 작업 만들기` 아님 — 옵션이 부족합니다)

## [일반] 탭

```
이름          전북대챗봇 학식수집
설명          생협 식단을 받아 서버로 보냅니다
              (해외 IP 가 막혀서 이 PC 에서 돕니다)

○ 사용자가 로그온할 때만 실행         ← 이걸 고릅니다
☑ 가장 높은 수준의 권한으로 실행       ← 체크
```

## [트리거] 탭 → `새로 만들기...`

```
작업 시작     매일
시작          (오늘 날짜)  06:00:00
매일          1 일마다

☑ 작업 반복 간격      5 시간   ← 목록에 없으면 직접 입력하세요
   기간                1 일
☑ 사용
```

`확인`.

> 06:00 에 시작해 5시간마다 → 06시 · 11시 · 16시 · 21시. 서버 수집 주기와 같습니다.

## [동작] 탭 → `새로 만들기...`

```
동작            프로그램 시작

프로그램/스크립트
powershell.exe

인수 추가(옵션)
-NoProfile -ExecutionPolicy Bypass -File "C:\Users\정영민\Desktop\전북대총학_카톡챗봇\jbnu-chatbot\scripts\push_meal.ps1"

시작 위치(옵션)
C:\Users\정영민\Desktop\전북대총학_카톡챗봇\jbnu-chatbot
```

★ 경로가 다르면 실제 폴더 경로로 바꿔 주세요.
  탐색기 주소창을 클릭하면 전체 경로가 나옵니다.

## [조건] 탭

```
☐ 컴퓨터의 AC 전원이 켜져 있는 경우에만 작업 시작   ← 체크 해제
   (노트북이면 배터리로도 돌아야 합니다)

☑ 작업을 실행하기 위해 절전 모드 해제              ← 체크
```

## [설정] 탭 ★ 여기가 제일 중요합니다

```
☑ 요청 시 작업이 실행되도록 허용
☑ 예약 시작 시간을 놓친 경우 가능한 대로 빨리 작업 시작   ← ★ 반드시 체크
☑ 작업이 실패하는 경우 다시 시작 간격    10 분
   다시 시작 시도 횟수                   3 회
```

★ **`놓친 경우 빨리 시작` 이 이 설계의 핵심입니다.**
  PC 가 꺼져 있었어도 켜면 곧바로 밀린 수집이 돕니다.
  그래서 **사람이 기억할 게 없습니다.** 컴퓨터를 켜기만 하면 됩니다.

`확인` → 암호를 물으면 윈도우 로그인 암호를 넣습니다.

## 걸었으면 바로 한 번 돌려 보기

목록에서 `전북대챗봇 학식수집` 을 오른쪽 클릭 → `실행`.
`마지막 실행 결과` 칸이 **`작업을 완료했습니다. (0x0)`** 이면 성공입니다.

# 5단계 ★ 돌았는지 확인하는 법

오늘 서버에서 **'돌긴 도는데 성공도 실패도 기록이 없는'** 상태를 겪었습니다.
같은 일이 이 PC 에서 조용히 반복되면 안 되므로, 확인할 자리를 네 군데 만들었습니다.

## ① 실패하면 바탕화면에 파일이 생깁니다

```
★학식_수집_실패.txt
```

열면 언제 · 왜 실패했는지 적혀 있습니다.
**다음번에 성공하면 이 파일은 저절로 사라집니다.**
낡은 경고가 남아 있으면 '또 실패했나' 를 매번 사람이 판단하게 되니까요.

★ 바탕화면에 이 파일이 없으면 마지막 실행은 성공한 것입니다.

## ② 서버에 직접 물어보기 (제일 확실합니다)

```
학식_상태_확인.bat   ← 두 번 클릭
```

```
================ 학식 자료 상태 ================

이 PC 의 마지막 실행
  2026-08-14 19:12:48  성공  1/1 성공

서버가 아는 것  (서버 시각 2026-08-14T19:13:02+09:00)
  마지막 성공  2026-08-14T19:12:48+09:00   (0.1 시간 전)

  ✅ 정상입니다. 최신 식단이 나가고 있습니다.
```

★ **PC 로그만 보면 안 되는 이유가 있습니다.**
  작업이 아예 안 돌았으면 PC 에는 **아무 기록도 안 남습니다.**
  없는 것을 알아채는 게 사람에게 제일 어렵습니다.
  그래서 '마지막으로 성공한 게 언제인가' 는 **서버가** 답하게 했습니다.

## ③ 작업 스케줄러 목록

`마지막 실행 결과` 칸을 보면 됩니다.

```
작업을 완료했습니다. (0x0)   성공
(0x1)                       서버가 거부했거나 자료를 못 받음
(0x2)                       SKILL_TOKEN 이 없음
(0x3)                       파이썬을 못 찾음
```

## ④ 기록 파일

```
jbnu-chatbot\logs\push_meal.log     지난 실행이 한 줄씩 쌓입니다
jbnu-chatbot\logs\LAST_RESULT.txt   마지막 결과 한 줄
```

# 만약 며칠 못 돌았다면

**챗봇이 틀린 답을 하지는 않습니다.** 자료가 하루 넘게 낡으면 학생에게 이렇게 나갑니다.

```
이건 8/12 자료예요. 그 뒤로 못 가져왔어요.
최신은 생협 식단표에서 확인해 주세요.
[생협 식단표 열기]
```

최신 식단을 못 보여줄 뿐, **없는 사실을 만들어내지 않습니다.**
그러니 며칠 못 켜셨어도 급하게 뭘 하실 필요는 없습니다 —
켜시면 밀린 수집이 저절로 돕니다.

# 자주 겪는 문제

| 증상 | 원인과 해결 |
|---|---|
| `(0x2)` · 토큰 없음 | 2단계에서 **사용자 변수**에 넣었을 수 있습니다. **시스템 변수**로 옮겨 주세요 |
| `(0x3)` · 파이썬 못 찾음 | 설치할 때 `Add python.exe to PATH` 를 체크 안 한 경우입니다. 다시 설치하며 체크 |
| `fetch 403` | 이 PC 도 막혔다는 뜻입니다. VPN 을 켜 두셨다면 끄고 다시 해 주세요 |
| `서버가 거부했다 401` | 토큰 값이 Render 의 값과 다릅니다. 2단계를 다시 |
| 작업이 안 돎 | [설정] 탭의 `놓친 경우 빨리 시작` 체크를 확인해 주세요 |

# 인수인계 (59대에게)

이 문서와 함께 넘길 것.

```
1. 이 PC 가 아니어도 됩니다 — 한국 가정용 인터넷이면 어느 PC 든 같습니다
2. SKILL_TOKEN 은 Render 대시보드에서 새로 확인하면 됩니다
3. 토큰이 새는 것 같으면 Render 에서 값을 바꾸고 2단계를 다시 하면 됩니다
```

★ 토큰은 카카오톡·이메일·문서에 붙여넣지 마세요. 저장소가 공개라 한 번 올라가면
  지워도 기록에 남습니다.
