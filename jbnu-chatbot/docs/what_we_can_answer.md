## 배포 전 남은 것

1. **오픈빌더 블록 연결** — `info.search`, `notice.search` 를 실제 블록으로 만들어야 학생이 쓴다
2. **크롤 스케줄 분리** — 안내 페이지는 하루 1회로 충분하다.
   식단·학사일정과 같은 주기로 돌리면 서버에 부담이고 우리에게도 낭비다
3. **T4 입력 창구** — 홈페이지에 없는 것(학점포기, 수강신청 정정, 기숙사 통금)은
   총학이 직접 넣어야 한다. 지금은 넣을 곳이 없다
4. `config/site_aliases.yaml` — 학생이 쓰는 말은 총학이 제일 잘 안다. 코드 수정 없이 늘릴 수 있다

# ② 표 렌더링 — (a) 를 다시 재고 또 멈췄다 (2026-08-17)

## 결론: (a) 의 사정거리가 **46문항 기준 0/5** 다

전체 코퍼스로는 그릴 수 있어 보였다.

```
table_row 잎 31,334개
  헤더 셀 수 = 행 셀 수      6,579  (21.0%)   ← 그릴 수 있다
  열 수 다름               24,270  (77.5%)
  헤더 못 찾음                485  ( 1.5%)
```

그런데 **실제 답에 나오는 표**로 재니 0 이다.

```
46문항 중 FOUND 30건 · 그중 인용이 표인 것 5건
  전부 kind='table' (표 전체)     → 헤더/행 셀 = 1/15, 1/21, 1/43 …
  kind='table_row' 는 0건
```

★ **인용은 자족성 승격 때문에 부모 블록(표 전체)으로 올라간다.**
  행 단위(table_row)는 인용에 안 나온다. 그래서 행 단위로 그리는 규칙은
  실제 답을 하나도 못 건드린다.

  이건 전에 표 전치를 되돌릴 때 적은 결론과 같다 —
  "필요하면서 가능한 건이 0건". 자를 바꿔도 그 결론이 유지된다.

## (b) 를 무조건 붙이면 읽히는 것도 버린다

그 5건의 인용을 보면 4건은 지금도 읽힌다.

```
성적 A+ 몇 점    등급 | 평점 | 비고 A+ | 4.5 | 95 ~ 100 …      셀 21 · 밀도 10.6%  읽힌다
수강신청 언제야    구분 | 내용 | 신청기간 개설교과목 신청 | …        셀 15 · 밀도  6.5%  읽힌다
편입학 학점인정    구분 | 내용 | 신청기간 계획수립 및 통보 | …        셀  9 · 밀도  7.0%  읽힌다
취업 상담       일 | 월 | 화 | 수 | 목 | 금 | 토 | | | 1 2 | 3 …  셀 43 · 밀도 21.9%  ★ 달력 위젯
```

## 막힌 자리 — '읽히나' 를 가를 자가 없다

자족성 판정기(is_self_contained)는 **43칸 달력까지 '이름:값 쌍' 으로 통과시킨다.**
지금 있는 자로는 못 가른다.

밀도(6.5~10.6% vs 21.9%)는 갈리지만 그건 임계값이다.
마진 1.00 에서 배운 것 — **임계값으로 푸는 건 다음에 코퍼스가 바뀌면 흔들린다.**

## 근본은 파서다

`kind='table'` 문단이 **헤더와 행을 한 줄로 붙여** 저장한다. 그래서 헤더 경계가 없다.
파서가 헤더를 별도로 남기면 (a) 가 가능해진다 — 재수집이 필요하다.

★ 다음에 볼 순서
```
1. 파서가 표 헤더를 별도 필드로 남기게 한다 (재수집)
2. 그러면 인용 단위가 표 전체여도 헤더+행으로 그릴 수 있다
3. 그때 (b) 는 '헤더가 없는 표' 로 좁혀진다 — 임계값이 아니라 관측이 된다
```
