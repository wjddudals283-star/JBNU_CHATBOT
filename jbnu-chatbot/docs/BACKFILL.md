# 노트북 백필 세팅 — 생협 원천

작성일 2026-08-11

---

## 왜 필요한가

생협 API 가 **Render(해외 IP)에서 403** 이다. 헤더 변형 7종과 일반 웹페이지까지
전부 막혔다(IP/지역 차단). 한국 IP 에서는 200 이다.

생협은 **1차 원천**이고, `date` 파라미터로 과거 조회가 되는 유일한 식단 원천이다.
학교 XHR 은 이번 주 고정이라 놓친 주를 영영 못 채운다. 그래서 우선순위를 안 바꾸고,
**한국 IP(노트북)에서 백필**하는 우회로 간다.

> 답변 품질은 이미 안 깨진다. `merge()` 가 "1차에 없고 2차에만 있는 칸은 2차 채택"
> 으로 처리하므로 학교 XHR 만으로 A분기가 나온다. 백필로 되찾는 건
> **교차검증 신호**와 **과거 데이터**다.

---

## 주기 — 주 2회 (월·목)

크롤 주기는 **신선도 임계 ÷ 2** 이하여야 한다. 같으면 여유가 0이라
한 번만 걸러도 즉시 stale 이 된다.

| | 값 |
|---|---|
| 생협 신선도 임계 | 192h (8일) |
| 허용 최대 간격 | 96h (4일) |
| 주 1회 | 168h → **위반** |
| **주 2회 (월·목)** | 96h → OK |

`config/sources.yaml` 의 `effective_cadence_hours: 96` 이 이 값이고,
`tests/test_schedule.py::test_모든_원천이_주기_규칙을_지킨다` 가 지킨다.

## 등록 절차 (Windows 작업 스케줄러)

### 1. 실행할 명령

저장소가 있는 폴더에서 이 한 줄이다.

```bat
python -m crawler.run --source coop_week_menu
```

### 2. 배치 파일 만들기

`jbnu-chatbot` 폴더에 `backfill.bat` 을 만든다. 경로는 본인 것으로 바꾼다.

```bat
@echo off
cd /d "C:\Users\정영민\Desktop\전북대총학_카톡챗봇\jbnu-chatbot"
python -m crawler.run --source coop_week_menu >> data\backfill.log 2>&1
```

> `>>` 로 로그를 남긴다. 조용히 실패하면 몇 주 뒤에나 알게 된다.

### 3. 작업 스케줄러 등록

1. 시작 → **작업 스케줄러** 실행
2. 오른쪽 **기본 작업 만들기**
3. 이름: `전북대챗봇 생협백필`
4. 트리거: **매주** → 시작 `오전 9:00` → **월요일, 목요일** 체크
5. 동작: **프로그램 시작** → 찾아보기 → 위에서 만든 `backfill.bat`
6. 마침 → **[속성] 대화 상자 열기** 체크 후 완료
7. 속성 → **조건** 탭
   - "컴퓨터의 AC 전원이 켜져 있는 경우에만..." **체크 해제** (노트북이면 중요)
8. 속성 → **설정** 탭
   - **"예약 시간을 놓친 경우 가능한 대로 빨리 작업 시작" 체크** ★
   - 노트북이 꺼져 있던 날을 따라잡는다. 이게 없으면 그 주는 통째로 빈다

### 4. 확인

작업 스케줄러에서 해당 작업을 우클릭 → **실행** 후 로그를 본다.

```powershell
Get-Content jbnu-chatbot\data\backfill.log -Tail 20
```

이렇게 나오면 정상이다.

```
[coop_week_menu] 생협 주간식단 (1차 원천)
  fetch 200  16,515B  hash=...
  outcome=success  파싱 95건 / 격리 0건  파서호출=True
```

`fetch 403` 이면 노트북도 차단된 것이다 — 그때는 대학 캠퍼스 망에서 시도해 본다.

## 과거 주 채우기

특정 주를 놓쳤으면 날짜를 지정한다.

```bash
python -m crawler.run --source coop_week_menu --date 2026-09-07
```

여러 주를 한 번에 채우려면 날짜를 바꿔가며 반복하면 된다.
같은 주를 두 번 넣어도 `UNIQUE` 가 막으므로 중복이 안 쌓인다.

---

## ⚠️ 이 백필은 배포 서버 DB 에 안 들어간다

노트북 백필은 **노트북의 로컬 DB**(`jbnu-chatbot/data/jbnu.db`)에 쌓인다.
Render 의 디스크와 별개다.

지금 이걸로 얻는 것:
- 과거 데이터 축적 (교차검증·분석용)
- 차단이 풀렸는지 주기적 확인

배포 서버에 반영하려면 3단계에서 Postgres 로 옮긴 뒤 양쪽이 같은 DB 를 보게 해야 한다.
그전까지는 **학생 답변은 학교 XHR 로 나가고**, 백필은 데이터 자산을 지키는 용도다.

이 한계를 모르고 "백필했으니 챗봇도 최신"이라고 생각하면 안 된다.

---

## 차단이 풀리면

배포 서버가 매일 스모크를 돌린다. 풀리면 로그에 이렇게 뜬다.

```
[smoke] BLOCK-LIFTED source=coop_week_menu 차단이 풀렸다 (통과: [...]).
```

그때 `config/sources.yaml` 의 `known_blocked` 와 `effective_cadence_hours` 를 지우고
`stale_after_hours` 를 24 로 되돌린 뒤 커밋하면 1차 원천이 복구된다.
