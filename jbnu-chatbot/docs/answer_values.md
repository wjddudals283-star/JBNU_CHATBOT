# 46문항 정답값 작성표

## 왜 필요한가

지금 `must_contain` 은 39건 중 **34건이 주제어**다. 질문에 이미 들어 있는 말을
인용에서 다시 찾는 것이라, 재고 있는 것은 "답했나" 가 아니라 **"주제가 맞나"** 다.

    수강신청 언제야  →  must '수강신청'    주제가 맞나
    성적 A+ 몇 점   →  must '4.5'        답했나        ← 5건뿐

37% 는 관련성 지표에 가깝고, 진짜 정답률은 **아직 모른다.**
정답이 무엇인지는 크롤도 검색도 못 정한다. 사람이 정해야 한다.

## 값을 문자열로 적지 않는다

    ✗  수강신청 언제야 → '8/25 10:00'    다음 학기에 전부 오답이 된다
    ○  수강신청 언제야 → DATE            학기가 바뀌어도 유효하다

학기마다 총학이 갱신하는 방식은 넣지 않는다 — 갱신을 잊으면 측정이
조용히 거짓말을 시작한다. 사람의 절제에 의존하는 건 설계가 아니다.

## 종류와 판정 방법

| 종류 | 뜻 | 코드 판정 | 난이도 |
|---|---|---|---|
| `DATE` | 날짜·시각 | 날짜 정규식 **+ 출처 페이지 + 신선도** | 가능 (삼중 검사 필요) |
| `PERIOD` | 기간 | `~`·`부터`·`까지`·`N주 전` 패턴 | 가능 |
| `MONEY` | 금액 | `N원`·`전액`·`면제`·`%` 패턴 | 가능 |
| `CREDIT` | 학점 수 | `N학점` 패턴 | 가능 |
| `NONE` | 제도가 없음 | T4 부정 답변 문안과 대조 | 가능 (확정적) |
| `ASK` | 되물어야 함 | `needs_attribute` 또는 되묻기 발동 여부 | 가능 (패턴 아님) |
| `REJECT` | 답하면 안 됨 | 지금 `expect="defer"` 그대로 | 가능 |
| `WHERE` | 장소·부서 | 조직·건물 이름 목록과 대조 | **부분적** |
| `STEPS` | 절차 | ★ 패턴으로 안 된다 | **어려움** |
| `COND` | 자격·조건 | ★ 패턴으로 안 된다 | **어려움** |

### ★ 어려운 둘 — `STEPS` · `COND`

`STEPS` 는 화살표나 번호 목록은 잡히지만 **순서가 틀려도 통과**한다.
`COND` 는 "2개 학기 이상 이수한 자" 처럼 자연어라 패턴이 거의 안 걸린다.

**대신 핵심 낱말 묶음으로 적어 주세요.** 값 하나가 아니라
"이 낱말들 중 K개 이상이 인용에 있어야 한다" 로 씁니다.

```yaml
자퇴 절차:
  kind: STEPS
  anchors: [OASIS, 자퇴원, 보호자, 학과장]
  min_hits: 3

복수전공 신청:
  kind: COND
  anchors: [2개 학기, 신청 자격, 휴학생]
  min_hits: 2
```

말이 바뀌어도 견디고, 규정은 학기마다 안 바뀌므로 썩지 않습니다.
그리고 순서를 못 재는 한계는 그대로 남습니다 — 그건 정직하게 못 재는 것으로 둡니다.

### ★ `DATE` 는 값 대신 삼중으로

```
형태    인용에 날짜 꼴이 있다
출처    그 인용이 학사일정 계열 페이지에서 나왔다     ← 아무 날짜나 못 통과
신선도   그 페이지 관측 시각이 N일 이내다              ← 지난 학기 날짜를 잡는다
```

셋이 다 맞아야 정답으로 셉니다. 학교가 일정을 안 갱신하면 신선도에서 걸리는데,
그게 우리가 잡아야 할 진짜 실패입니다.
