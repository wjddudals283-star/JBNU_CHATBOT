## 요약 — 세 줄

1. **식단표는 이미지가 아니다.** 세 원천 모두 구조화돼 있다(JSON 1 + HTML 테이블 2). VLM 파싱 분기는 폐기한다.
2. **원천이 하나가 아니라 둘이다.** 생협 API에는 메뉴만, 학교 XHR에는 메뉴 + **가격 + 운영시간**이 있다. 둘을 합쳐야 완성되고, 합치면 §5 교차검증이 실제로 가능해진다.
3. **가격은 날짜에 붙어 있지 않다.** 별도 단가표에 품목명으로 붙어 있다. `menu_item.price`를 크롤로 채운다는 전제가 깨진다 → §6 스키마 수정 필요.

## 조사 1 — jbnu.ac.kr 식단안내 XHR 엔드포인트

**결과: 찾았다. Playwright 없이 확보.**

```
POST https://www.jbnu.ac.kr/web/unvrslife/campuslife/cafeteria/dataAjax.do
  data    : type=day  |  type=rest
  headers : X-CSRF-Token: <메타태그 값>   ★없으면 403
            AJAX: true
            Referer: .../cafeteria.do
  cookie  : JSESSIONID  (cafeteria.do 를 먼저 GET 해서 획득)
  응답    : text/html;charset=UTF-8  — JSON 아님. HTML 조각
```

CSRF 토큰은 `cafeteria.do` 본문의 `<meta name="_csrf" content="...">`에서 꺼낸다. 세션 바인딩이므로 **같은 클라이언트로 페이지 GET → AJAX POST** 순서를 지켜야 한다. 토큰 없이 호출하면 200이 아니라 403 + "접근이 거부되었습니다" HTML이 온다.

`date` 파라미터는 **받지 않는다.** `date` / `sdate` / `searchDate` 를 넣어도 응답 바이트가 완전히 동일했다. **이번 주(월~금) 고정.**

### `type=day` 응답 구조 — 테이블 10개

| # | 내용 | 식당 | 행 |
|---|---|---|---|
| 0 | 운영시간 | 진수원 | 점심·석식 |
| 1 | 가격 | 진수원 | 백반 구성원 7,000 / 외부인 8,500 |
| 2 | 주간식단 | 진수원 | 조·점·석 |
| 3 | 운영시간 | 의대식당 | 점심 |
| 4 | 가격 | 의대식당 | 백반 구성원 7,000 / 외부인 8,500 |
| 5 | 주간식단 | 의대식당 | 점·석 |
| 6 | 운영시간 | 후생관 | 조식·점심 |
| 7 | 가격 | 후생관 | "메뉴 가격 보기" (표 9로 위임) |
| 8 | 주간식단 | 후생관 | 13코너 |
| **9** | **후생관 메뉴 단가표** | 후생관 | **34행 · 분류/코너/메뉴/단가/비고** |

`type=rest`는 같은 데이터의 **당일치 전치(轉置)** 뷰다(4×4). 정보량이 `type=day`의 부분집합이므로 **크롤은 `type=day`만** 하면 된다.

주간식단 테이블 헤더에 실제 날짜가 박혀 있다 — `월요일 2026-08-10` … `금요일 2026-08-14`. 날짜를 추론할 필요가 없다.

## 조사 2 — coopjbnu.kr 빈 응답 원인

**결과: 빈 응답이 아니다. 기존 관측이 틀렸다.**

| 단계 | 결과 |
|---|---|
| ① httpx 기본 UA | **200 · 24,965 B** — 여기서 이미 성공 |
| ② 브라우저 UA | 200 · 24,965 B (바이트까지 동일) |
| ③ Playwright | **불필요** |

봇 차단이 아니다. 페이지 껍데기는 서버렌더로 정상 도착하고, **식단만 jQuery AJAX로 채워진다.** `week_menu.php` 본문에 `<div id="all_cafeteria_data">주간 식단 데이터를 불러오는 중입니다...</div>` 자리표시자가 있고, 인라인 스크립트가 이걸 교체한다. 예전에 "빈 응답"으로 본 것은 이 자리표시자를 본 것이거나 일시적 장애였을 것이다.

### 발견한 엔드포인트

```
POST https://coopjbnu.kr/function/get_cafeteria_menu.php
  data : date=YYYYMMDD  [, now=Y]
  응답 : application/json; charset=utf-8
```

**인증·Referer·쿠키·브라우저가 전부 불필요하다.** Referer 없는 맨몸 POST가 동일 응답을 준다. 세 원천 중 크롤 난이도가 가장 낮다.

### 응답 스키마

```jsonc
{
  "status": "success",
  "list": [
    {
      "restNm": "후생관",          // 진수원 | 의대식당 | 후생관  (3곳 고정)
      "date":   "2026-08-10",
      "day":    0,                  // 0=월 … 4=금
      "subData": [
        { "cate1": "점심",          // 조식 | 점심 | 석식
          "cate2": "한식",          // 한식|양식|분식|포크프리존|''  (구역)
          "cate3": "찌개*돌솥",     // 코너
          "diet":  "돈목살짜글이*계란후라이\n\n" }   // \n 구분 품목 목록
      ]
    }
  ]
}
```

전 응답을 훑어 확인한 키는 위 8개가 전부다(`date, subData, day, restNm` / `cate1, cate2, cate3, diet`). **가격 필드는 존재하지 않는다.** 여러 날짜를 통틀어 `\d{3,}` 또는 `원` 패턴이 걸린 diet 라인은 **0건**이었다.

### `now` 파라미터의 의미 ★크롤 단위를 결정한다

| 호출 | 반환 |
|---|---|
| `POST now=Y` | 해당 **1일** (3식당 × 1일 = 3건) |
| `POST now=N` / `now` 생략 / `GET` 아무거나 | 해당 주 **월~금 전체** (3 × 5 = **15건**) |

→ **`now`를 빼고 POST 한 번이면 그 주가 통째로 온다.** 이걸 크롤 단위로 삼는다. (GET은 `now`를 무시한다. PHP가 `$_POST`만 읽는 것으로 보인다.)

### 데이터 커버리지 경계 ★인텐트 설계에 직결

2026-08-10부터 45일을 1일 단위로 훑었다.

```
08-10(월) ● 08-11(화) ● 08-12(수) ● 08-13(목) ● 08-14(금) ●
08-15(토) · 08-16(일) · … 09-23(수) ·   ← 이후 전부 0건
```

- **토·일은 항상 0건.** 운영시간표의 "주말·공휴일 미운영"과 일치 → `closed_holiday`로 매핑.
- **다음 주 이후는 0건.** 미래 데이터가 아예 없다.
- 과거는 최소 **2025-09-01**까지 조회된다(테스트 픽스처 확보에 충분).

> **`status:"success"` + `list:[]` 는 "미운영"이 아니라 "아직 안 올라옴"이다.**
> 이 응답만으로는 방학·휴일·미게시를 구분할 수 없다. 운영시간표(조사 1)와 대조해야 구분된다.
> 결론: **"다음 주 메뉴" 질문은 원천이 없다.** §9 "원천 없는 인텐트는 만들지 않는다"에 따라 백로그로 보낸다. 답할 수 있는 범위는 **이번 주 월~금**뿐이다.

## 대조군 — likehome (생활관 주간식단)

**서버렌더 HTML 테이블 확인. 예상대로 동작한다.**

- `date=2026-08-10` 요청 → **`date=2026-08-09`로 302 리다이렉트.** 그 주의 **일요일**로 정규화된다. 주 단위 뷰이므로 요청 날짜와 최종 URL이 다른 것은 정상이다. 크롤러는 리다이렉트 후 URL을 `source_url`로 기록해야 한다.
- 표는 4행 × 8열 고정: 헤더행(일~토) + 아침/점심/저녁 3행.

### T2 테스트 케이스 실측 확인 ★

| 날짜 | 표 | 데이터 셀 |
|---|---|---|
| 2026-08-10 (방학) | **구조 정상** (4행 32칸) | **전부 빈칸** |
| 2026-06-01 (학기중) | 구조 정상 | 25칸 채워짐 |

핸드오프 §0의 경고가 실측으로 확인됐다. **표는 멀쩡한데 칸만 비어 있다.** 이걸 `parse_error`로 처리하면 T2 실패다 → `service_status='closed_vacation'`, `items=[]`.

### 미운영 표현 사전

| 원천 | 표현 | 매핑 |
|---|---|---|
| 생협 / 학교 | `운영없음` | `closed_temporary` (코너 단위) |
| 생활관 | `식사없음` | `closed_temporary` |
| 생활관 | `[지방선거]` `[대체공휴일]` | `closed_holiday` + note에 사유 보존 |

이 문자열들이 `menu_item.name`으로 저장되면 챗봇이 **"오늘 메뉴: 운영없음"**이라고 답한다. 파서 단계에서 걸러야 한다.

## ★ 함정 — selectolax `css("td,th")`는 문서 순서를 지키지 않는다

조사 중 실제로 밟았고, 하마터면 사양서에 잘못 적을 뻔한 문제다.

`row.css("td,th")`는 **셀렉터별로 묶어서** 반환한다(td 전부 → th 전부). 그래서 행 머리글 `<th>`가 **행 끝으로 밀려 보인다.**

```python
# 잘못 — 라벨이 행 끝에 온 것처럼 보인다
row.css("td,th")
#   ['', '흰밥 소고기샤브국…', '잡곡밥 미역국…', '[지방선거]', …, '아침']

# 올바름 — 자식 노드를 순회한다
[n for n in row.iter(include_text=False) if n.tag in ("td","th")]
#   ['아침'(th), ''(td), '흰밥 소고기샤브국…', '잡곡밥 미역국…', '[지방선거]', …]
```

**증상이 조용하다.** 파싱은 성공하고 예외도 안 나는데 **모든 메뉴가 하루씩 밀린다.**
실제로 처음 읽었을 때 `[지방선거]`가 화요일(6/2)에 걸렸는데, 바로잡으니 수요일 **6/3**이었다 — 제9회 전국동시지방선거일과 일치한다. 정렬이 맞다는 물증이다.

→ `parsers/` 전체에 **`css("td,th")` 사용 금지**. 공용 헬퍼 `row_cells(row)` 하나를 두고 강제한다. 테스트에도 넣는다(아래 T15).

## 스키마·계약 수정 제안 (핸드오프 §8 "예상과 다른 필드")

### 1. `menu_item.price` — 크롤로 못 채운다 ★가장 큰 변경

가격은 **날짜별 식단이 아니라 별도 단가표**에 있고, 키가 **품목명**이다.

```
후생관 메뉴 단가표 (dataAjax type=day, table[9])
  분류 / 코너 / 메뉴 / 단가 / 비고
  한식 / 조식 / 백반            / 6,000원        / 천원의 아침밥 이벤트시 1,000원
  양식 / 돈가스 / 등심돈까스     / 6,000원
  양식 / 오므라이스 / 스페셜오므라이스 / 6,000원 - 6,500원   ← 범위 표기
  분식 / 우동 / 유부우동         / 3,000원        / 곱빼기(+)500
  분식 / 라면 / 공기밥           / 1,000원
  …34행
진수원·의대식당: 백반 구성원 7,000원 / 외부인 8,500원 (단일 가격)
```

문제는 **단가표의 품목명과 식단표의 품목명이 일치하지 않는다**는 것이다.
단가표 `등심돈까스` ↔ 식단표 `통등심돈까스`, 단가표 `계란라면` ↔ 식단표 `신라면`.
이름 조인은 깨진다.

**제안**: `menu_item.price`를 크롤 대상에서 빼고 **`menu_price` 테이블을 신설**한다. T1(식단)과 T2(가격)는 갱신 주기가 다르므로 어차피 분리가 옳다.

```sql
CREATE TABLE menu_price (
  id TEXT PRIMARY KEY,
  facility_id TEXT NOT NULL REFERENCES facility(id),
  category TEXT,              -- 분류 (한식|양식|분식|포크프리존)
  corner TEXT,                -- 코너
  item_name TEXT NOT NULL,
  item_name_normalized TEXT NOT NULL,
  price_min INTEGER, price_max INTEGER,   -- '6,000원 - 6,500원' / '6,000원 부터'
  price_note TEXT,            -- '곱빼기(+)500', '천원의 아침밥 이벤트시 1,000원'
  audience TEXT,              -- 구성원|외부인|NULL
  -- 공통 출처 메타 8개 …
  tier TEXT NOT NULL DEFAULT 'T2'
);
```

답변 템플릿은 **가격을 품목 옆에 붙이지 않고** "가격표 보기" 버튼으로 뺀다. 이름이 안 맞는데 억지로 붙이면 그게 곧 오답이다. (데모 HTML이 품목마다 가격을 붙여 보여주는데, 그 화면은 실제 데이터로는 만들 수 없다. 데모 수정 필요.)

### 2. `corner` 한 칸으로는 부족하다

원천은 2단이다 — `cate2`(구역: 한식/양식/분식/포크프리존) + `cate3`(코너: 찌개*돌솥/특식/돈까스류…). 후생관은 하루에 **13개 조합**이 나온다.

**제안**: `meal_service`에 `zone TEXT` 추가, `corner`는 `cate3` 전용.
`UNIQUE(facility_id, date, meal_type, corner)` → `UNIQUE(facility_id, date, meal_type, zone, corner)`.
(`돌솥`이 `찌개*돌솥`과 별도 코너로 또 나오므로 zone 없이는 충돌 위험이 있다.)

### 3. `meal_type` 매핑

원천 표기는 `조식 / 점심 / 석식`이다. **`중식`이 아니다.**
`조식→breakfast`, `점심→lunch`, `석식→dinner`. `aliases.yaml`에 고정한다.

### 4. 빈 `diet` 와 `운영없음`은 다른 신호다

| 신호 | 사례 | 해석 |
|---|---|---|
| `diet == "운영없음"` | 후생관 조식·석식 (방학) | 명시적 미운영 → `closed_temporary` |
| `diet == ""` | 진수원 조식, 의대식당 조식·석식 | **모호** |

빈 문자열은 운영시간표와 대조해야 판정된다. 의대식당 운영시간표에는 **점심만** 있다 → 조식·석식은 애초에 안 하는 끼니 → `closed_vacation`이 아니라 "해당 없음". 진수원은 점심·석식만 있다.

**제안**: 운영시간표에 없는 끼니는 `meal_service` 레코드를 **생성하지 않는다.** 있는데 비면 `unknown`. 이러면 "진수원 아침 뭐야?"에 "진수원은 아침을 운영하지 않아요"(B분기)로 답할 수 있다.

### 5. 방학이라고 전부 닫는 게 아니다 — 데모의 B분기 문안 수정 필요

2026-08-10(방학) 실측:

| 식당 | 조식 | 점심 | 석식 |
|---|---|---|---|
| 진수원 | (없음) | **운영** | **운영** |
| 의대식당 | (없음) | **운영** | 빈칸 |
| 후생관 | 운영없음 | **운영** (11코너) | 운영없음 |

데모의 `"후생관은 방학이라 오늘은 운영하지 않아요"`는 **사실과 다르다.** 방학에도 점심은 돈다. 문안을 끼니·코너 단위로 바꿔야 한다.

### 6. `source_type` 값 추가

`facility.source_type`에 `official|coop|council|thirdparty`가 있는데, 생활관은 어디에도 안 맞는다. **`dorm` 추가.**

### 7. 별칭

`restNm`은 `의대식당`인데 생협 페이지 JS는 `의대`로 매칭한다. `진수원`은 설계문서의 `진수당`과 다르다 — **원천 표기는 `진수원`이 맞다.** `aliases.yaml`에 양쪽 다 넣는다.

| source_key | 엔드포인트 | 티어 | 주기 | 얻는 것 |
|---|---|---|---|---|
| `coop_week_menu` | `get_cafeteria_menu.php` (POST, `now` 생략) | T1 | 06:00/10:30/16:00 | 주간 메뉴 (3식당×5일) |
| `jbnu_cafeteria_day` | `dataAjax.do?type=day` (+CSRF) | T1·T2 | 일 1회 | 메뉴 교차검증 · **가격** · **운영시간** |
| `likehome_week_menu` | `inner.php?sMenu=B7100&date=` | T1 | 06:00/16:00 | 생활관 3식 |

**교차검증이 실제로 가능하다.** 생협 API와 학교 XHR이 같은 주의 같은 식단을 독립적으로 제공한다 → 설계문서 §5-4 "원천 2개 이상이면 불일치 시 우선순위 채택 + `conflict` 플래그"를 D5에서 바로 구현할 수 있다. 우선순위는 **생협 API 우선**(날짜 지정 가능, 인증 불필요)으로 두고 학교 XHR을 검증자로 쓴다.

**셀렉터 위험도**: 생협 JSON API는 셀렉터가 없다 = 사이트 개편에 가장 강하다. 학교·생활관은 `selectors.yaml`로 외부화한다.
